# ONEv2 펌웨어 입력 소스 제어 경로 (Ghidra 디컴파일로 확정)

도구: Ghidra 12.1.4 헤드리스 + AVR32(`avr32:BE:32:default`), 베이스 `0x80000000`, 자동분석 후 디컴파일. 대상 `ONEv2_USB_Audio_Image0.bin`(뱅크0).

주소는 함수 자동탐지 결과의 Ghidra 기본 이름(`FUN_<addr>`)이다. 모두 **[확인]** — 실제 디컴파일로 검증.

## USB 벤더 요청 → 입력 전환 호출 사슬

```
USB EP0 벤더 요청 (bmRequestType 0x40/0xC0, bRequest=N)
  └─ FUN_800093d4(src, setup_pkt, cb)           # 벤더 디스패처: switch(setup_pkt[1]=bRequest)
       ├─ 읽기(GET, bmRequestType bit7=1): 각 케이스가 상태를 읽어 반환
       └─ 쓰기(SET): 공통으로 FUN_800093ac → 데이터 단계 수신(버퍼 0x2454) → FUN_80009088
            └─ FUN_80009088(buf, cb): switch(buf[1]=bRequest)
                 └─ case 0x36:  FUN_8000aa30(*data, 3)     # ← 마이크 입력 소스 설정
```

- **디스패처 `FUN_800093d4`**: `switch(param_2[1])` = bRequest. 케이스가 요청표와 1:1(0x10,0x14,0x1f,0x20,0x26,0x27,0x28,0x29,0x31,0x33,0x34,0x35,**0x36**,0x3e,0x3f,0x44,0x48,0x4c–0x4f,0x53…). `cVar2 < 0`(bmRequestType bit7)로 GET/SET 분기.
- **0x29(킵얼라이브)**: 순수 게터. 클록 소스·샘플레이트·상태를 6바이트로 묶어 반환(쓰기 경로 없음). 호스트가 주기적으로 읽는 이 동작이 곧 워치독 리셋이다. stevebrodie 리눅스 프로젝트가 4초마다 보내는 그 요청과 동일.

## 입력 소스 setter — 패치의 핵심 지점

**`FUN_8000aa30(int new_type, int mode)`** = 마이크 입력 소스 설정 함수.
```c
if (_DAT_0000255c != new_type) {       // 0x255c = 현재 입력 타입 상태변수 (0=내장,1=외장,2=외장48V)
    _DAT_0000255c = new_type;
    ... 오디오 경로 재구성 (_DAT_000004xx + FUN_8000ccc4) ...
}
```
- **상태변수 `0x0000255c`** = 현재 마이크 입력 타입. 게터 `FUN_8000a248`(0x36 GET)이 여기서 읽는다.
- USB 0x36 쓰기는 `FUN_8000aa30(받은바이트, 3)`을 호출한다. **노브 제스처 패치는 같은 함수를 `FUN_8000aa30((현재+1)%3, 3)`로 호출하면 된다.**

## 물리 경로 구동 (GPIO/아날로그 스위치)

**`FUN_8000a250()`** = `0x255c` 값에 따라 핀을 구동. `FUN_8000e360(reg,val)`은 최다 참조(120회) GPIO/코덱 레지스터 설정 헬퍼.
| 입력 타입 | 호출 |
|---|---|
| 0 내장 | e360(0x18,1) e360(0x19,1) e360(0xd,0) e360(0xe,0) |
| 1 외장 | e360(0x18,0) e360(0x19,0) e360(0xd,0) e360(0xe,0) |
| 2 외장+48V | e360(0x18,0) e360(0x19,0) e360(0xd,1) e360(0xe,1) |
→ 0x18/0x19 = 내장 마이크 경로, 0xd/0xe = 48V 팬텀. (reg 번호가 GPIO 핀인지 코덱 레지스터인지는 FUN_8000e360 내부 확인 필요 — 다음 과제.)

## USB 문자열 디스크립터 핸들러 (참고)

`FUN_80008170`: 표준 요청 처리. `bRequest==6`(GET_DESCRIPTOR), 타입 3(문자열), `switch(wValue & 0xff)`: index 0x11=iAP, 0x12=Internal Mic, 0x13=External Mic, 0x14=External 48V. 디스크립터의 iTerminal 18/19/20과 일치.

## 부팅 기본값 / 초기화

`FUN_8000a658()`: ~40개 설정 전역을 기본값으로(입력타입 `0x255c=0`, 게인 0x30, 샘플레이트 48000 등) 세팅 후 `FUN_8000a590()` 호출. 공장초기화/부팅 경로.

## 다음 과제 (device-side 목표)

1. **인코더 핸들러 찾기.** 노브 회전/푸시 이벤트를 처리하고 "어떤 레벨을 조절할지"(인코더-셀렉트 상태)를 바꾸는 함수. 인코더-셀렉트는 `FUN_8000c484()`가 읽는 상태(0x48 GET이 이를 매핑). 이 상태를 **쓰는** 함수가 버튼 처리부다. 거기에 더블/트리플클릭·롱프레스 감지를 넣어 `FUN_8000aa30((cur+1)%3, 3)`을 호출하면 노브만으로 입력 전환이 된다.
2. FUN_8000e360 내부를 봐서 reg 번호의 물리적 의미(GPIO 핀 vs 코덱 레지스터) 확정.
3. 패치 적용·재배치·뱅크별 반영·무결성(업데이터 페이지 리드백) 전략 — 실기기 JTAG 백업 확보 후.
