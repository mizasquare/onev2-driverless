# Apogee ONE v2 — 목표와 펌웨어 요구사항 명세

확정 2026-10-01. 기기: Apogee ONE v2, USB 0c60:0017, MCU Atmel AVR32 UC3A3/A4, 펌웨어 1.05.

## 사용할 환경과 목표 (우선순위)

- **대상 플랫폼:** 윈도우, 맥, 아이패드(USB-C).
- **[1순위] USB 클래스 컴플라이언트 동작** — 벤더 드라이버·호스트 소프트웨어 없이 세 플랫폼 모두에서 입출력이 되게 만든다. 특히 아이패드는 호스트 측 구제(피더·커스텀 드라이버)가 원천 불가하므로, 기기가 **순수 표준 장치로 혼자 완결**돼야 한다.
- **[2순위(중상)] 호스트 소프트웨어 의존성 제거** — 펌웨어 고치는 김에, 인코더(노브) 조작만으로 입력 소스를 전환하게 한다.

둘 다 **펌웨어 수정(Strategy C)** 으로 달성한다. 호스트 측 해결(드라이버 설치, 피더 데몬)은 아이패드에서 막히므로 1순위를 만족시키지 못한다.

## "죽는 원인" = 요구사항 (각 플랫폼 실패 단계 정리)

연결 단계: ① 열거 → ② 드라이버 시작 → ③ 스트리밍 → ④ 세션 유지(워치독)

| 플랫폼 | 실패 단계 | 원인 | 고쳐야 할 것 |
|---|---|---|---|
| 윈도우(내장 usbaudio2) | ② | 디스크립터 규격 위반 거부(코드10/0xC0440022) | R1 |
| 리눅스(생 snd-usb-audio) | ③~④ | 초기화 누락 + 워치독 자가 분리 | R2 |
| macOS | 실패 없음 | (관대 + EP0 트래픽이 워치독 먹임) | — |
| USB-C 아이패드 | 입력만 실패 | 표준 경로로 입력 소스 전환/등록 안 됨(MFi/iAP 의존) | R3, R4 |

## 펌웨어 요구사항

### R1 — 디스크립터 4개 결함 수정 [1순위, 데이터 패치]
클록 소스 id 중복 / 오디오 IAD가 벤더 IF3 포함 / 피처유닛 bLength 10→18 / AC 헤더 wTotalLength 174→167.
- 위치: 디스크립터 테이블이 평문으로 이미지 내 `0x17614`(config A), `0x17768`(config B), device desc `0x175F4`에 있음. 뱅크별로 따로 적용.
- 상태: **위치 확인됨.** 순수 데이터 패치. 난이도 중. → 윈도우 내장 드라이버가 받아들이게 됨.

### R2 — 자가 분리 워치독 제거/무력화 [1순위, 코드 패치]
~9초간 EP0 제어 요청이 없으면 기기가 USB에서 스스로 분리. 아이패드·생 리눅스에서 치명적.
- 상태: **타이머/ISR 미특정.** EVBA(0x80016C00) 인터럽트 벡터 + 타이머 주변장치 추적 필요. 확정 후 "타임아웃 무한대" 또는 "detach 호출 제거"로 무력화.
- 주의: 0x29 핸들러 자체엔 리셋 코드 없음 → 워치독은 하위 계층. 제거 대상은 타이머가 호출하는 detach 쪽.

### R3 — 표준 UAC2 셀렉터 유닛을 실제 입력 전환에 연결 [1순위, 코드 패치 — 핵심 미확인]
디스크립터에 셀렉터 유닛 id 15가 있지만, **표준 SET_CUR이 실제 입력 setter를 부르는 경로가 아직 확인 안 됨.**
- 확인된 것: 입력 setter `FUN_8000aa30`의 호출자는 둘뿐 — (a) 벤더 0x36 핸들러, (b) 스테이징 적용 함수 `FUN_800072c4`(전역 0x3c에서 값, iAP/호스트 커맨드 경로로 추정). **표준 UAC2 셀렉터 SET_CUR 경로는 없어 보임.**
- 함의: 그래서 USB-C 아이패드가 입력을 못 잡을 개연성이 큼(순수 UAC2로는 소스 전환 불가). 컴플라이언트 펌웨어는 **셀렉터 유닛 15의 SET_CUR/GET_CUR을 FUN_8000aa30/FUN_8000a248에 연결**해야 함.
- 상태: **다음 과제 1순위.** "표준 셀렉터가 이미 wiring 돼 있는가"를 먼저 확정(안 돼 있으면 추가, 돼 있으면 R3 불요).

### R4 — iAP 없이 캡처 스트림 동작 보장 [1순위, 조사 필요]
USB-C 아이패드에서 출력은 되는데 입력이 "어떤 앱에도 등록 안 됨". 캡처 경로가 iAP 초기화에 의존하는지 확인 필요.
- 상태: 미확인. R3와 함께 조사.

### R5 — 인코더 제스처 → 입력 전환 [2순위, 코드 패치]
노브 더블/트리플클릭·롱프레스로 `FUN_8000aa30((현재+1)%3, 3)` 호출.
- 확인된 것: setter(FUN_8000aa30)와 상태변수(0x255c) 확정. GPIO 구동(FUN_8000a250), 인코더 상태 읽기(FUN_8000c484)도 확인.
- 상태: **인코더 이벤트 핸들러(버튼 처리부) 미특정.** 그걸 찾아 제스처 감지 삽입.

## 공통 전제 (절대 조건)

- **어떤 펌웨어 쓰기 전에 실기기 JTAG 풀백업.** 부트로더/DFU 영역(0x80000000–0x80003FFF)은 업데이트 파일에 없음 → 손상 시 복구 불가. 주말에 2x5 헤더가 JTAG인지 확인 + 보안 비트 확인이 선행.
- 이중 뱅크(0x80004000 / 0x80024000): 패치는 양쪽 반영(+0x20000 재배치 고려). 업데이터는 서명 강제 안 함(페이지 리드백만) → 수정 이미지 수용 가능성 높음(확정은 실기기에서).

## 작업 순서

1. **R3/R4 확정 조사** (지금 가능, 디스어셈블): 표준 셀렉터 wiring 여부 + 캡처-iAP 의존 여부. → 1순위 작업량 확정.
2. **R2 워치독 타이머 특정** (디스어셈블): EVBA 벡터 + 타이머.
3. **R5 인코더 핸들러 특정** (디스어셈블).
4. (실기기) JTAG 헤더·보안비트 확인 → 풀백업.
5. 패치 설계 → 뱅크 반영 → 플래시 → 검증.

## 클라우드 재구성 반영 (2026-10-01): R2–R5 위치 확정

클라우드 세션이 전체 디스어셈블(399함수)로 아키텍처를 재구성. 산출물: `resources/cloud-reconstruction/FIRMWARE_ARCHITECTURE.md`, `FUNCTION_INVENTORY.txt`. 가장 중요한 R2 arm 지점은 로컬에서 바이트·디스어셈블로 교차검증 완료.

- **R1 (디스크립터):** 변동 없음. 테이블 0x17614/0x17768/0x175F4, 뱅크별 +0x20000.
- **R2 (워치독) — 위치 확정 + 로컬 검증:** 소프트 타이머가 아니라 **하드웨어 WDT @ 0xFFFF0D30**. 부팅 init(FUN_80010C88)에서 **단 한 번** 키 시퀀스로 arm: `0x80010CD6`(키1 0x55001301), `0x80010CEC`(키2 0xAA001301), CTRL=0x1301 → 프리스케일 19 → 약 9.11초. 만료 시 **칩 전체 리셋**(USB detach+재열거). "EP0 요청마다 리셋"은 관측된 효과였고 실제론 주기적 pet이 없음 — reconfig 이벤트(FUN_80010674 @0x800106F4)에서만 clear. **패치: 두 키 쓰기 무력화 또는 EN 비트 클리어로 WDT 비활성화.** 리터럴은 파일 0x1107c/0x11080(+0x20000 뱅크1). ← P1 핵심 레버.
- **R3 (셀렉터) — 위치 확정 + 확정 결론:** 인터페이스 수신 핸들러 `0x80008432`는 **SET_INTERFACE(0x0b)만** 처리. 셀렉터/피처/클록 유닛의 SET_CUR/GET_CUR은 디코드 안 돼 **STALL**. 표준 클래스 핸들러 없음 → 입력 전환은 벤더 0x36로만 가능(= 클래스 비컴플라이언트). **패치: 0x80008432에 SET_CUR 핸들러 추가 → FUN_8000AA30 연결.**
- **R4 (캡처-iAP) — Image0 한정 확인:** 캡처 alt-setting은 제네릭 ASF(FUN_80008084), iAP/벤더 게이트 없음. 단 iAP 플래그 0x18C4가 Image0에서 write-only → 소비자가 Image1(미분석)에 있을 가능성. **실기기에서 캡처가 막히면 Image1부터 확인.**
- **R5 (인코더) — 위치 확정:** 핸들러 **FUN_8000CB40**(메인루프 0x80010EDE), GPIO 엣지 ISR 0x8000D5E8+ → 링버퍼 0x271C, 9상태 vtable 0x8000C370 → 선택상태 0x2648. **패치: FUN_8000CB40 또는 새 vtable 상태에서 제스처 감지 → FUN_8000AA30(type,mode) 직접 호출.** 참고: FUN_8000CAF0 = 입력타입 순환기(폴링루프).
- **주변장치/라우팅:** WDT 0xFFFF0D30, GPIO 0xFFFF1000, USBB 0xFFFE0000, TWIM0(코덱 I2C) 0xFFFF2C00, SSC(I2S) 0xFFFF3400 등. FUN_8000E360=GPIO 핀 쓰기(코덱 아님). 핀: PA10/PA07=내장마이크, PB20/PB22=48V.
- **신규 주의 — 진단/제조 블록:** 벤더 요청 0xA0–0xD0이 제조/플래시 커밋 인터페이스(0xa2/0xa7 플래시 연산, 0xa6 공장복원 FUN_8000A658). 클린 컴플라이언트 빌드는 이걸 노출하면 안 되고, 플래시 쓰기 경로 이해의 단서이기도 함.

**정정:** 기존 "워치독 = EP0 요청마다 리셋 / 4초마다 먹이면 생존" 서술은 관측 효과였음. 실제는 하드웨어 WDT를 init에서 arm, reconfig 때만 pet. 우리 목표(컴플라이언스)에서는 **먹이는 게 아니라 arm을 패치해 끈다** — 이게 아이패드에서 유일하게 통하는 길.
